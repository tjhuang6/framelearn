# 问题解答

## Q1: 关键帧为什么会没有时间戳？现在的字幕是有时间戳的啊

**A:** 关键帧确实有时间戳，但**代码里没有记录下来**。

当前实现：
```python
# FFmpegHelper.extract_keyframes()
# 只返回了图片路径列表：[frame_001.jpg, frame_002.jpg, ...]
# 没有返回每张图片对应的视频时间（比如 00:03:45）
```

FFmpeg 的 `showinfo` 滤镜输出里**有**时间信息（`pts_time`），但是：
1. `extract_keyframes()` 只把图片保存下来
2. 把 `showinfo` 的日志丢弃了
3. 后续流程完全不知道 `frame_001.jpg` 是在视频的第几秒截的

**结果：**
- 字幕有时间戳：`00:01:23 现在我们讲解 FastAPI`
- 关键帧没时间戳：`frame_001.jpg` 不知道对应第几秒
- LLM 只能"猜测"图片应该插在哪段文字后面，而不是精确对应

**修复方案：**
1. 解析 FFmpeg 的 `showinfo` 输出，提取 `pts_time`
2. 返回 `[(frame_001.jpg, 83.5), (frame_002.jpg, 157.2), ...]`（路径 + 秒数）
3. 生成教材时：找到时间最接近的字幕段落，把图片插到那里

## Q2: 现在完全就是一个 workflow，根本就不是一个 Agent 呀

**A:** 对，**当前版本就是 workflow，不是 Agent**。

### 什么是 workflow
- 固定步骤：提取音轨 → ASR → 清洗 → 关键帧 → 生成教材
- 每步都是确定性的脚本
- 不会根据中间结果调整策略
- 类似工厂流水线

### 什么是 Agent
- 能观察环境、做决策、调整计划
- 比如：
  - 发现字幕质量差 → 自动切换 ASR 模型重试
  - 发现关键帧太少 → 降低场景检测阈值重新提取
  - 发现生成的教材缺少代码 → 重新解析字幕找代码段
- 有反馈循环，不是一条路走到黑

### FrameLearn 现在的状态

**workflow 部分（主流程）：**
```
VideoPipeline.run()
  → FFmpegHelper（脚本工具）
  → ASRAdapter（调用 API）
  → SubtitleCleaner（正则脚本）
  → KeyframeDeduplicator（算法脚本）
  → DocumentGenerator（调用 LLM，但只调一次）
```

**Agent 痕迹（很弱）：**
- `DocumentGenerator` 调用 LLM 生成教材
- 但只调一次，不会检查质量、不会重试、不会自我修正
- LLM 在这里只是"生成器"，不是"智能体"

### 为什么不是 Agent？

**缺少的能力：**
1. **自我评估** — 生成的教材质量如何？需要改进吗？
2. **错误恢复** — ASR 失败了怎么办？切换方案还是放弃？
3. **动态规划** — 3 小时视频应该分几章？根据内容决定还是固定切 10 分钟？
4. **工具调用链** — 发现字幕里提到"完整代码见 GitHub"，要不要自动去爬？

### 如何变成 Agent？

**方向 1：教材生成环节加反馈循环**
```
生成初稿 
→ 让另一个 LLM 评审（代码是否完整、解释是否清晰）
→ 根据评审意见重写
→ 再评审 → 直到质量达标
```

**方向 2：主流程加决策节点**
```
ASR 识别 
→ 检查字幕质量（准确率、完整性）
→ 质量不够 → 换模型重试 / 调整参数 / 人工介入
→ 质量 OK → 继续
```

**方向 3：引入 Codex 的 Agent 模式**
- 不写死流程，只给目标："把视频转成教材"
- Codex 自己决定：
  - 先做什么（ASR？还是先看关键帧？）
  - 用什么工具（FFmpeg？还是调 YouTube API 拿字幕？）
  - 遇到问题怎么办（字幕缺失 → 尝试 OCR 识别屏幕文字）

### 总结

- **现在**：FrameLearn 是一个"自动化脚本"，恰好调了 LLM
- **Agent 化需要**：让 LLM 参与决策、评估、修正，而不只是"生成内容"
- **成本**：Agent 模式会多调很多次 LLM（评审、重试、规划），token 消耗大
- **trade-off**：workflow 便宜、可控；Agent 灵活、质量高

当前版本选择 workflow 是合理的（MVP 阶段），后续可以逐步 Agent 化。
