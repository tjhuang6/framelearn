# FrameLearn 处理流程概览

本文档描述 FrameLearn 从字幕到教材的三个核心步骤的实现原理。

---

## 1. 字幕清洗（SubtitleCleaner）

**目标**：把 ASR 输出的原始文本转换为干净、易读的字幕。

### 处理步骤

1. **去除干扰内容**
   - 删除括号内的标注：`[音乐]`、`(掌声)`、`【笑声】`
   - 使用正则表达式匹配并移除

2. **全角转半角**
   - 中文标点（`，。！？`）→ 英文标点（`,. ! ?`）
   - 统一标点符号格式，便于后续处理

3. **去重**
   - ASR 有时会输出重复的句子
   - 按行比较，连续重复的只保留一次

4. **优化断句**
   - 在句号、问号、感叹号后插入换行符
   - 让每句话独立成行，结构更清晰

5. **清理空白**
   - 移除多余的空格和空行
   - 最多保留两个连续换行（分段）

### 输入输出示例

**输入（ASR 原始输出）：**
```
[音乐]现在我们来讲解，，FastAPI的使用方法。。
现在我们来讲解，，FastAPI的使用方法。。
首先要安装依赖（掌声）
```

**输出（清洗后）：**
```
现在我们来讲解, FastAPI的使用方法.
首先要安装依赖
```

## 2. 关键帧提取（FFmpegHelper + KeyframeDeduplicator）

**目标**：从视频中提取讲师切换 PPT 页或写代码的瞬间，作为教材插图。

### 第一阶段：FFmpeg 场景检测

使用 FFmpeg 的 `scenedetect` 滤镜：

```bash
ffmpeg -i video.mp4 \
  -vf "select='gt(scene,0.3)',showinfo" \
  -vsync 0 \
  frames/frame_%04d.jpg
```

**参数说明：**
- `scene=0.3`：场景变化阈值（0.3 表示画面变化超过 30% 就截图）
- 适合检测 PPT 翻页、代码编辑器切换等明显变化
- 输出的帧可能有几百张（对于长视频）

**备用策略：**
- 如果视频没有明显场景切换（比如纯讲话，没有 PPT），自动降级为固定间隔截图
- 默认每 30 秒截一帧

### 第二阶段：图片去重

**问题**：FFmpeg 可能会在同一张 PPT 上截取多帧（比如讲师指着屏幕讲了 2 分钟）。

**解决方案（KeyframeDeduplicator）：**

1. **计算图片相似度**
   - 使用感知哈希（pHash）算法
   - 把每张图片转换为 8×8 的灰度缩略图
   - 计算 DCT（离散余弦变换）系数
   - 生成 64 位指纹（哈希值）

2. **汉明距离比较**
   - 比较两张图片的哈希值的二进制差异
   - 差异小于阈值（默认 5 bit）→ 视为重复
   - 差异大 → 视为不同画面

3. **保留代表帧**
   - 对于相似的一组帧，只保留第一张
   - 最终输出 20-100 张关键帧

### 示例

**输入（FFmpeg 输出）：**
```
frame_0001.jpg  ← PPT 第 1 页
frame_0002.jpg  ← PPT 第 1 页（讲师在讲解，画面没变）
frame_0003.jpg  ← PPT 第 1 页（还在讲）
frame_0004.jpg  ← PPT 第 2 页（翻页了）
frame_0005.jpg  ← PPT 第 2 页
frame_0006.jpg  ← 切到代码编辑器
```

**输出（去重后）：**
```
frame_001.jpg  ← PPT 第 1 页
frame_002.jpg  ← PPT 第 2 页
frame_003.jpg  ← 代码编辑器
```

## 3. 教材生成（DocumentGenerator）

**目标**：把字幕和关键帧整合成结构化的 Markdown 教材。

### 两种模式

1. **notes 模式**：课堂笔记风格
   - 按章节列出知识点（bullet points）
   - 适合快速复习

2. **textbook 模式**：正式教材风格
   - 完整段落叙述
   - 适合系统学习

### 处理流程

#### 3.1 构建 Prompt

把字幕和关键帧信息整理成一个结构化的提示词：

```
你是一个编程教材编写助手。根据视频字幕和关键帧，生成 Markdown 教材。

# 字幕原文
<subtitle>
现在我们来讲解 FastAPI...
</subtitle>

# 关键帧列表
<frames>
1. src/frame_001.jpg
2. src/frame_002.jpg
...
</frames>

# 输出要求
- 按内容自然分章节
- 提取所有代码片段并标注语言
- 在合适位置插入关键帧：![说明](src/frame_001.jpg)
- 去除口水词，保留技术信息
- 输出 Markdown 格式
```

#### 3.2 调用 LLM

**方式 1：app-server 模式（默认）**
- 启动 Codex app-server 子进程
- 把 prompt 和关键帧图片发送过去
- app-server 调用 GPT-4V 或 Claude 3.5 Sonnet
- 返回生成的 Markdown

**方式 2：API 模式**
- 直接调用 Vision API（DeepSeek/OpenAI/Anthropic）
- 关键帧转 base64 编码
- 构建多模态消息：`[{text: prompt}, {image: base64_1}, {image: base64_2}, ...]`
- 一次请求发送所有内容

#### 3.3 提取生成结果

**app-server 模式的特殊处理：**
- Codex 不直接返回 Markdown 内容
- 而是把内容写到文件（如 `output/xxx/index.md`）
- 然后返回一句话："已整理完成，文件在 output/xxx/index.md"
- FrameLearn 会捕获 `fileChange` 事件，读取实际写入的文件内容
- 再把内容写回到正确的输出路径

**API 模式：**
- 直接返回 Markdown 文本
- 写入 `output/任务名/index.md`

### 最终输出

```
output/视频名/
  index.md          ← 教材版（textbook）
  notes.md          ← 笔记版（notes）
  src/
    frame_001.jpg   ← 关键帧图片
    frame_002.jpg
    ...
    subtitle.txt    ← 清洗后的字幕
    subtitle.srt    ← 带时间戳的字幕（如果 ASR 支持）
```

## 技术栈总结

| 组件 | 技术 | 作用 |
|------|------|------|
| 字幕清洗 | Python 正则表达式 | 去噪、标准化文本 |
| 场景检测 | FFmpeg scenedetect | 识别画面切换 |
| 图片去重 | pHash + 汉明距离 | 移除重复帧 |
| 教材生成 | GPT-4V / Claude 3.5 Sonnet | 多模态理解 + Markdown 生成 |
| 多模态传输 | base64 编码 / Codex RPC | 把图片发给 LLM |

## 优化点

### 当前实现的问题
- 长视频（3 小时）字幕一次性发给 LLM 会超出上下文
- 关键帧没有时间戳，无法和字幕精确对应

### 下一步改进方向
1. **分章节生成**
   - 按 10-20 分钟切分字幕
   - 每章单独生成，最后合并
   - 避免上下文窗口限制

2. **关键帧时间对齐**
   - 记录每个关键帧的视频时间戳
   - 和字幕时间戳对应
   - 生成教材时精确插入到对应段落

3. **增量生成**
   - 已生成的章节缓存起来
   - 下次运行只生成未完成部分
   - 支持断点续传

这些改进将在后续版本中实现。
