# 教学视频转写与字幕生成方案总结

## 1. 方案结论

针对最长约 3 小时、以单人讲解为主的教学视频，推荐采用以下方案：

```text
FFmpeg 切片
→ 上传私有 OSS
→ 阿里百炼 paraformer-v2 并行转写
→ 合并词级时间戳
→ 字幕切分与后处理
→ 输出 SRT / VTT / JSON
```

该场景不需要说话人分离，也不需要维护跨分段的讲师身份。第一版应优先保证实现简单、处理速度快和字幕时间戳可靠。

## 2. Paraformer 推荐配置

```json
{
  "model": "paraformer-v2",
  "input": {
    "file_urls": ["https://OSS临时地址/chunk_001.m4a"]
  },
  "parameters": {
    "timestamp_alignment_enabled": true,
    "diarization_enabled": false,
    "disfluency_removal_enabled": false,
    "language_hints": ["zh", "en"]
  }
}
```

关键参数：

- `timestamp_alignment_enabled: true`：启用时间戳校准，为字幕生成提供可靠时间轴。
- `diarization_enabled: false`：单人教学视频不需要说话人分离。
- `language_hints: ["zh", "en"]`：适合中文讲解中夹杂英文术语。
- `disfluency_removal_enabled: false`：MVP 保留原始表达，避免删除语气词后造成文字与时间轴不自然。

## 3. 长音频切片和并行识别

3 小时音频建议按约 30 分钟切成 6 段，并发提交识别任务。

第一版可以直接无重叠切片，以最快速度完成开发。若实际测试发现切片边界偶尔丢字，再为相邻片段增加约 2 秒重叠，并在合并时去除重复内容。

完整处理步骤：

1. 使用 FFmpeg 将音频切成约 30 分钟一段。
2. 将所有分段上传到 OSS。
3. 同时提交多个 Paraformer 识别任务。
4. 等待所有任务完成。
5. 将每段的局部时间戳加上该段在原音频中的起始偏移量。
6. 如果使用了重叠切片，删除重叠区的重复文字。
7. 生成完整的 SRT、VTT 和 JSON 文件。

## 4. OSS 临时地址的作用

百炼长音频识别通常通过 HTTP/HTTPS 地址拉取文件，而不是直接接收本地文件上传。因此，需要先把音频放到对象存储，再生成一个有时效的签名下载链接。

推荐流程：

```text
用户上传音频
→ 后端将分段上传至私有 OSS
→ 生成 24 小时有效的签名 URL
→ 将 URL 提交给 Paraformer
→ 识别并生成字幕
→ 删除 OSS 中的临时音频
```

签名 URL 的特点：

- 只允许访问指定文件。
- 不暴露 OSS AccessKey 密钥。
- 到期后自动失效。
- 无需公开整个 Bucket。
- 识别完成后可以立即删除源文件。

对于长音频，建议有效期设为 24 小时，不要只设 30 分钟，以免任务排队、处理或重试导致链接提前过期。

数据库应保存 OSS 对象名，例如：

```text
audio-tasks/task-123/chunk-001.m4a
```

不要长期保存完整签名 URL，因为 URL 会过期；需要时可根据对象名重新签名。

OSS 并非唯一选择，只要百炼能够通过公网 HTTP/HTTPS 下载即可，也可以使用 COS、S3、R2 或自建下载服务。但在使用阿里百炼时，OSS 通常集成最简单、国内传输稳定。

## 5. 热词和课程词汇表

专业教学内容常包含技术术语、英文缩写、软件名称、人名、品牌、公式、函数名和变量名。为每门课程提供热词或课程词汇表，往往比更换识别模型更能直接提高准确率。

示例：

```json
{
  "course_terms": [
    "Python",
    "FastAPI",
    "WebSocket",
    "Paraformer",
    "Kubernetes"
  ]
}
```

产品层面可以允许用户上传 `课程词汇.txt`，或在提交任务时填写专业词汇。

## 6. 字幕后处理规则

获得词级时间戳后，应由字幕程序重新组织文本，而不是直接使用模型返回的长句。

建议规则：

- 每条字幕持续约 1～7 秒。
- 每行中文约 12～20 个字。
- 每条最多两行。
- 优先在逗号、句号和问号处切分。
- 遇到约 500～800 毫秒以上的停顿时切分。
- 不拆开英文单词、数字或专业术语。
- 相邻字幕的时间范围不能重叠。

时间轴应以 Paraformer 的词级时间戳为基础，再根据标点、停顿和长度规则生成字幕块。

## 7. 大语言模型的使用边界

大语言模型只适合做轻量文本纠错，例如：

- 修正专业术语和明显的同音错字。
- 根据课程词汇表纠错。
- 优化标点。
- 添加合理的中英文空格。

不应让大语言模型：

- 大幅改写原句。
- 用总结替代原始字幕。
- 合并时间上距离很远的语句。
- 自行修改时间戳。

职责划分应保持清晰：

```text
Paraformer：生成文字和时间戳
字幕程序：切分字幕并管理时间轴
大语言模型：可选的轻量纠错
```

## 8. MVP 技术选型

第一版推荐：

- 后端：Python + FastAPI
- 音频处理：FFmpeg
- 文件存储：阿里云 OSS
- 语音识别：阿里百炼 `paraformer-v2`
- 异步处理：FastAPI `BackgroundTasks` 或简单任务表
- 字幕生成：Python
- 输出格式：SRT、VTT、JSON

正式版可逐步增加：

- Redis + Celery 或 RQ
- 任务进度查询
- 自动失败重试
- 热词管理
- 在线字幕编辑
- 大语言模型术语纠错

## 9. 最小核心功能

```text
上传音频
→ 30 分钟切片
→ 并行转写
→ 合并全局时间戳
→ 生成字幕
```

这条路线实现成本低、结构清晰，适合先快速完成三小时单人教学音频的字幕 MVP。
