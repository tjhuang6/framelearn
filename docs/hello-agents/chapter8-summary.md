# 第八章《记忆与检索》学习笔记

## 概述

本章在第七章框架基础上，为 HelloAgents 添加两个核心能力：**记忆系统（Memory System）**和**检索增强生成（RAG）**。目标是让智能体能够跨会话记住信息、从外部知识库中检索事实，解决 LLM 天生无状态、知识静态的两个根本局限。

## 问题从哪里来：LLM 的两个根本局限

**局限一：无状态导致遗忘。** LLM 每次 API 调用都是独立的，不会自动记住上一轮对话。在同一进程内，`SimpleAgent._history` 可以暂存最近上下文，但这份历史不跨会话持久化，也不能被精准检索或有选择地遗忘。

**局限二：内置知识是静态的。** 模型知识有训练截止点，特定领域深度不足，也无法引用来源——容易出现"幻觉"。RAG 的思路是：在模型生成回答之前，先从外部知识库中检索最相关的片段，将这些片段作为上下文一起送入模型，用"检索"来补位"记忆"。

## 记忆系统的设计思路

记忆系统借鉴认知心理学的分层结构，把不同生命周期、不同用途的信息分开存储。四种记忆类型对应四种典型场景：

| 类型 | 解决什么问题 | 存储方案 | 生命周期 |
|------|-------------|---------|---------|
| 工作记忆 | 当前会话的临时信息 | 纯内存 + TTL | 会话级，自动过期 |
| 情景记忆 | 具体事件和时间序列 | SQLite + Qdrant | 持久化，可跨会话检索 |
| 语义记忆 | 抽象知识和概念关系 | Qdrant + Neo4j | 长期，支持知识图谱 |
| 感知记忆 | 图像、音频等多模态 | SQLite + Qdrant（多集合） | 持久化 |

这种分层不只是分类，更是工程上的性能权衡：工作记忆要快（纯内存），情景记忆要能过滤时间段（SQLite），语义记忆要能做图关系查询（Neo4j）。

## MemoryTool：统一接口

记忆能力以工具形式暴露给 Agent，接口是统一的 `execute(action, **kwargs)`，action 包括：`add`、`search`、`summary`、`forget`、`consolidate` 等。

添加记忆时，工具会自动补充 `session_id`、`timestamp` 等元数据，并按 `importance`（0.0–1.0）标记重要程度：

```python
memory_tool.execute("add",
    content="用户张三是一名 Python 开发者，专注机器学习",
    memory_type="semantic",
    importance=0.8
)

memory_tool.execute("search",
    query="前端工程师",
    limit=3
)
```

### 工作记忆的检索评分

工作记忆采用混合检索，优先 TF-IDF 向量化，失败时回退关键词匹配，综合评分公式为：

```
final_score = (向量相似度 × 0.7 + 关键词匹配 × 0.3) × 时间衰减 × (0.8 + 重要性 × 0.4)
```

时间衰减用指数模型：`exp(-0.1 × age_hours / 24)`，24 小时内保持高分，之后逐渐衰减。

### 情景记忆与语义记忆

情景记忆用 SQLite 存结构化字段（方便按时间段、会话 ID 过滤），同时用 Qdrant 存向量（方便语义检索）。语义记忆额外对接 Neo4j，在写入时自动提取实体和关系构建知识图谱，检索时可以做"向量检索 + 图检索"的混合策略。

### 遗忘机制

记忆系统提供三种遗忘策略：基于重要性（清除低重要性记忆）、基于时间（清除过时记忆）、基于容量（容量满时移除最低优先级）。这和人类记忆的选择性遗忘一致——不是简单地堆积信息，而是主动维护信息质量。

## RAG 系统：从文档到可检索知识

RAG 把外部知识处理为两个阶段：**数据准备**（文档 → 分块 → 向量化 → 入库）和**查询应用**（问题 → 检索 → 拼入 prompt → 生成回答）。

### 文档处理：统一转 Markdown

所有格式的文档（PDF、Word、HTML 等）都用 `MarkItDown` 先转为 Markdown，再做分块。这个设计的好处是：Markdown 结构（标题层级 `#`、`##`、`###`）本身携带语义分界，分块算法可以直接基于标题层级切割，而不是盲目按字数截断。

分块还支持重叠（`chunk_overlap`）：后一块保留前一块尾部若干 token，防止语义在边界处断裂。针对中英文混合文本，用专门的 token 估算函数（CJK 字符按 1 token 计，其他字符按空格分词计）保证分块大小准确。

### 嵌入方案的三级降级

为了兼顾不同部署环境，嵌入服务做了三级降级：
1. **百炼 API（DashScope）**：云端高质量嵌入
2. **本地 Transformer（all-MiniLM-L6-v2）**：离线部署
3. **TF-IDF**：轻量兜底，无需额外依赖

### 两种高级检索策略

**MQE（多查询扩展）**：对用户原始问题生成多个改写版本（不同角度、不同表述），分别检索后合并结果，提升召回率。适用于问题表述不精确的场景。

**HyDE（假设文档嵌入）**：先让模型对问题生成一段假设性的答案，用假设答案的向量去检索知识库（而不是用问题的向量）。直觉是：答案的向量空间和知识库文档更接近，比问题向量检索的精度更高。

### RAGTool 接口

```python
# 添加知识文档
rag_tool.execute("add_document",
    file_path="doc.pdf",
    chunk_size=1000,
    chunk_overlap=200
)

# 检索
rag_tool.execute("search",
    query="如何优化 Pandas 内存？",
    strategy="hyde",  # 或 "basic"、"mqe"
    top_k=5
)
```

## 综合案例：智能文档问答助手

本章实战案例把 RAGTool 和 MemoryTool 结合为一个 PDF 学习助手：

- 加载文档时，RAGTool 负责"PDF → Markdown → 分块 → 向量化"，MemoryTool 以情景记忆记录"加载了哪个文档"
- 提问时，RAGTool 检索相关片段，MemoryTool 检索历史学习记录，两路结果合并后送入 LLM
- 用户添加笔记，记录到语义记忆，最终汇总为学习报告

这个模式体现了 Memory 和 RAG 的分工：**Memory 管"我经历过什么"，RAG 管"知识库里有什么"**。

## 与 FrameLearn 的关联

FrameLearn 的问答模块是本章知识的直接落地场景。

**RAGTool 对应 FrameLearn 的问答模块**。用户对生成好的 Markdown 教程提问时，问答模块需要从 Markdown 文档中检索相关段落作为上下文。本章介绍的"Markdown 智能分块"策略（基于标题层级分割 + 重叠）恰好适配 FrameLearn 的输出格式——生成的教程本身就是结构化 Markdown，分块可以直接利用 `##` 边界。Chroma 向量数据库的用法和本章 Qdrant 原理相同，可以直接迁移向量检索和评分思路。

**记忆系统对应 FrameLearn 的多轮问答上下文管理**。单次问答结束后，用情景记忆记录"用户问过什么"，下次提问时可以利用历史做更连贯的回答，避免每次问答都从零开始。

**遗忘机制对应长视频处理中的信息管理**。处理长视频时，规划 Agent 和内容分析器会产生大量中间信息（转录文本片段、关键帧描述等）。工作记忆的 TTL 机制和容量管理策略，可以参考用于控制这些临时信息的生命周期，防止上下文无限膨胀。

**MQE 和 HyDE 对提问质量的提升**。FrameLearn 用户的提问往往是"这段讲的是什么意思"这类不精确的问题，MQE 的多角度改写扩展能显著提升召回率；HyDE 的假设文档策略在教程类内容上也更贴近文档语言风格，值得作为优化方向引入。
